# Financial safety

Bursar enforces financial invariants at the canonical account boundary:

- Each mutation locks the account before calculating a new balance.
- An idempotency key maps to one ledger entry per account.
- The account balance must equal the sum of its ledger entries.
- Available lot amounts must equal derived bucket totals.
- A strict-prepaid operation cannot cross its minimum balance.
- Leases reserve capacity and can settle only once.
- Refunds and expiry are reversal entries, never projection rewrites.

```python
grant = bursar.credits.add_credits(
    user_id, 100, idempotency_key="checkout:42"
)
charge = bursar.credits.deduct_credits(
    user_id, 10, idempotency_key="operation:42"
)
refund = bursar.credits.refund_credits(charge.entry_id)
```

For long-running work, create a lease before execution, renew it while work is
alive, then settle the actual amount or release it on failure. Team charges use
the same posting path and store the member as the ledger actor.

Spend caps, allowance windows, feature limits, and maximum concurrency are
account-plan policy. They do not duplicate the monetary balance.
